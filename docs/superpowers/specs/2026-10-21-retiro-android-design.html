Retiro del cliente Android y su soporte

Diseño aprobadoPress-Ticket2026-10-21

Contexto

El frontend se empaqueta actualmente como APK mediante Capacitor. El código asociado incluye frontend/android/, scripts/configuración de build, adaptadores Capacitor para preferencias y refresh tokens, y notificaciones FCM para Android. El backend conserva además PushTokens y Users.mobileNotificationsEnabled. Se autorizó borrar los tokens registrados y la preferencia móvil mediante migración.

El refresh token web continúa funcionando mediante la cookie jrt HttpOnly, withCredentials y el endpoint /auth/refresh_token; ese flujo no debe cambiar. Las notificaciones del navegador de la agenda de recordatorios tampoco dependen de Android y deben permanecer.

Objetivos

  1. Retirar del repositorio el proyecto Gradle/Capacitor y la generación del APK.
  2. Eliminar las dependencias npm y el código frontend exclusivo de Capacitor, FCM, modo móvil y preferencias nativas.
  3. Eliminar endpoints/servicios FCM del backend, sus callers y la dependencia firebase-admin.
  4. Eliminar encabezados de refresh nativo, conservando la sesión web con cookies.
  5. Aplicar una migración que borra PushTokens y Users.mobileNotificationsEnabled.
  6. Retirar las instrucciones versionadas para compilar el APK.

Decisión

Se elimina todo el soporte de ejecución Android, no solo el wrapper Capacitor. Se quitan el directorio Gradle versionado, capacitor.config.ts, build-android-apk.bat, dependencias y código runtime. También se elimina la UI de modo móvil, las traducciones de esa UI, el registro FCM y las notificaciones FCM de mensajes/canales.

Backend: eliminar rutas/controlador/servicio push, modelo PushToken de Sequelize, propiedad mobileNotificationsEnabled, llamadas al servicio push, firebase-admin, headers CORS nativos y X-Refresh-Token. El refresh web seguirá usando la cookie jrt.

Datos: la migración 20261021020000-remove-android-push-support.ts elimina la tabla PushTokens y la columna Users.mobileNotificationsEnabled. El down recrea el esquema vacío: no recupera los tokens ni preferencias anteriores. Las dos migraciones históricas se conservan.

Los archivos de build no versionados, credenciales externas Firebase/Infisical y publicación de Play Store no se alteran. El APK previamente instalado deja de recibir soporte del servidor; no se intenta desinstalarlo ni retirar su listado de Play Store.

Fuera de alcance

  • Eliminar el soporte web o el formulario web de configuración del backend.
  • Cambiar el refresh token web por cookie.
  • Retirar las notificaciones del navegador usadas por recordatorios.
  • Borrar credenciales externas, archivos de IA/ o logs locales.
  • Modificar archivos de documentación push locales no versionados.
  • Despublicar la aplicación en Google Play.

Pruebas y aceptación

  1. No hay paquetes @capacitor/* en package/lockfiles.
  2. No hay referencias de runtime a Capacitor, FCM, `X-Client-App`, `X-Refresh-Token`, PushToken o mobileNotificationsEnabled fuera de migraciones históricas.
  3. El frontend web compila y mantiene URL de backend en localStorage.
  4. Tests de sesión confirman login/refresh por cookie y ausencia de headers nativos.
  5. La migración elimina tabla/columna y su rollback recrea estructuras vacías.
  6. La agenda conserva notificaciones web y su alarma interna.

Despliegue y rollback

La migración corre antes del reinicio backend. Verificar su estado up, el panel y las sesiones. Para rollback, deshacer la migración antes de volver a código que usa esos campos; el esquema se recrea vacío y los datos borrados no se restauran.
